# 响应规律与严格正则编写（通用框架 + 平台速查）

> 本文件分两部分：**通用部分**（3GPP 标准 AT 指令的跨平台响应骨架，几乎所有模组一致）
> 用于新平台从零起步；**平台速查部分**（各厂商/型号固件实测的细节差异）用于已勘测的平台快速套用。
>
> 核心原则（SKILL.md）：写严格断言**只以目标平台文档为准**，不照搬其他固件规律。
> 本文件提供「骨架」帮你起步，**冒号后空格数、数据行格式以目标平台文档描述为准**
> （文档不明时用实测探查补齐，但断言标准始终是文档——见 SKILL.md 步骤 5）。

---

## 第一部分：通用响应骨架（跨平台，3GPP 标准）

所有 AT 指令响应以 `\r\n`（0x0D 0x0A）分帧。ATProbe 原始字节不经规范化（无 strip/replace），
故断言可直接对 `\r\n` 做精确匹配。

### 响应类别

| 类别 | 终结符 | 典型形态 |
|---|---|---|
| **成功（无数据）** | `OK` | `\r\nOK\r\n` |
| **成功（带数据行）** | `OK` | `\r\n+CMD: <data>\r\nOK\r\n` |
| **业务码（非 OK 终结）** | 自定义码 | `\r\n+CMD: <message>\r\n`（无 OK 尾随） |
| **CME 错误** | `+CME ERROR:` | `\r\n+CME ERROR: <code>\r\n` |
| **CMS 错误（SMS 类）** | `+CMS ERROR:` | `\r\n+CMS ERROR: <code>\r\n` |
| **通用 ERROR** | `ERROR` | `\r\nERROR\r\n` |

### A. 查询/设置成功 —— OK 结尾

```
\r\n[+CMD: <data>\r\n]?OK\r\n
```

数据行统一是 `+CMD:` + **空格**（数量以**文档描述**为准，通常 1 个）+ `<value>`。
**冒号后的空格数以文档为准**（文档不明时再实测探查并记录，但断言以文档描述为标准）。

### B. 业务码 —— 不以 OK 结尾

业务码（如 `+TCPSETUP: ERROR`、`+FTP: ERROR`）不终结于 OK，框架遇 OK/ERROR 才终结判定，
故**业务码响应必须加 `timeout`**（见 SKILL.md 业务码超时陷阱）。

### C. 错误码 —— CME / CMS / 通用 ERROR

- **`+CME ERROR: <code>`**：移动设备错误（3GPP TS 27.007 §9.2）。常见码：
  | 码 | 含义 | 常见触发 |
  |---|---|---|
  | 3 | operation not allowed | 状态不允许（如已激活再激活） |
  | 10 | SIM not inserted | 无卡 |
  | 11 | SIM PIN required | 需 PIN |
  | 13 | SIM failure | SIM 故障 |
  | 50 | operation not performed | 需 PDP 激活但未激活 |
  | 53 | invalid parameter / not allowed | 参数越界、格式错、链路号超范围 |
  | 58 | unknown command | 指令名拼错/不支持 |
- **`+CMS ERROR: <code>`**：短消息错误（3GPP TS 27.005 §3.2.5）。SMS 类指令（CMGS/CMGR）用此。
- **`ERROR`**（裸）：通用错误，无具体码。

> 不同固件对同一场景可能返回不同码（如参数错有的返 53、有的返通用 ERROR）。**以目标平台文档描述为准。**

### D. 异步指令 —— OK 受理 + URC 结果

异步指令（建链/拨号/长耗时操作）：参数合法时先返 `OK`（仅受理），随后主动上报 URC 才是真正结果。
同步指令成功直接返 `OK`（无后续 URC）。**同步/异步判定只看文档**（见 SKILL.md「同步/异步指令陷阱」）。

异步用例配 `wait_urc`，框架遇 OK 不终结、读到匹配 URC 才返回（整段响应含 OK+URC）。

## 第二部分：平台速查（实测细节，按平台分节）

> 以下是已勘测平台的实测细节。**新平台勿照搬**——先用通用骨架起步，实测确认后在此追加本平台小节。

### N58（Neoway N58，固件 N58-R07-STD-OE_V20_MEITUAN-00F）

本项目 ch06 实测验证（与文档一致）。其他指令集（HTTP/FTP/MQTT 等）大概率遵循同样规律，以各章节文档为准。

**数据行空格规律**：
| 类型 | 真实响应（·=空格） | 严格正则 |
|---|---|---|
| 无数据行（设置成功） | `··OK` | `^\r\nOK\r\n$` |
| 数据行1空格 | `··+NETAPN:·"cmnet","",""` | `^\r\n\+NETAPN: "[^"]*","[^"]*","[^"]*"\r\nOK\r\n$` |
| 数据行多空格（右对齐） | `··+XIIC:····0,0.0.0.0`（冒号后4空格） | `^\r\n\+XIIC:    \d+,[\d.]+\r\nOK\r\n$` |
| 取值范围（测试命令） | `··+RECVMODE:·(0-1),(0-1)` | `^\r\n\+RECVMODE: \(0-1\),\(0-1\)\r\nOK\r\n$` |
| 多数值 | `··+TCPKEEPALIVE:·0,120,75,9` | `^\r\n\+TCPKEEPALIVE: \d+,\d+,\d+,\d+\r\nOK\r\n$` |

规律：数据行统一是 `+CMD:` + **恰好1个空格** + `<value>`，**XIIC 例外**（冒号后4空格，右对齐填充）。

**业务码**：
| 指令 | 真实响应 | 严格正则 |
|---|---|---|
| 链路操作失败 | `··+TCPSETUP:·ERROR` | `^\r\n\+TCPSETUP: ERROR\r\n$` |
| 消息体含空格 | `··+TCPSEND:·SOCKET·ID·OPEN·FAILED` | `^\r\n\+TCPSEND: SOCKET ID OPEN FAILED\r\n$` |
| 状态查询 | `··+IPSTATUS:·0,DISCONNECT` | `^\r\n\+IPSTATUS: 0,DISCONNECT\r\n$` |

**CME 错误码区分**（53 vs 58 很重要）：
- 53 = 参数无效 / 不允许（指令认得但参数错）
- 58 = 指令未识别 / 不支持（指令名拼错/固件未编入）
- 50 = 操作未执行（需 PDP 激活但未激活）

## 严格正则编写要点（通用，适用所有平台）

1. **`\r\n` 显式写**：在 YAML 正则里写 `\r\n`（反斜杠+r、反斜杠+n），它会被 `re` 引擎解释为
   CR+LF，匹配真实响应里的 0x0D 0x0A。不要写成 `\\r\\n`（双反斜杠会变成字面反斜杠+r）。
2. **空格用字面空格**：写几个空格就匹配几个，**不要用 `\s` 或 `\s*`**（它们会匹配任意数量，
   失去严格性）。在 YAML 单引号字符串里直接敲空格即可。
3. **`^...$` 锚定整段**：`^` 匹配响应开头，`$` 匹配结尾。这保证"恰好"，杜绝多余/缺失字符。
4. **正则元字符转义**：`+` → `\+`，`(` → `\(`，`)` → `\)`，`.` → `\.`（当要匹配字面时），
   `?` 在字符类外要转义。`-` 在字符类内 `[0-9]` 不用转义。
5. **数值占位**：`\d`（1位）、`\d+`（多位）、`[\d.]+`（IP 等）。
6. **引号内容**：字符串值用 `"[^"]*"`（不含引号的任意字符）匹配。

## matches vs contains 选择（通用）

- `matches`：用正则，做严格格式校验（本 skill 的核心手段）。底层是 `re.search`，但配合
  `^...$` 锚定后等同全匹配。
- `contains`：子串包含，用于"只要出现就行"的宽松场景（如错误码判断 `contains: "+CME ERROR: 53"`）。
- `not_contains`：不包含，用于反证（如确认业务码响应里 `not_contains: "+CME ERROR"`）。

严格字节级校验一律用 `matches` + `^...$`。

## 新平台响应勘测起步流程

拿到一个全新平台/固件、**文档不明确或缺失**时，按以下步骤勘测响应规律，补齐文档未覆盖的细节。
注意：勘测的目的是**补文档不明之处**（如文档未写冒号后空格数）；文档明确的部分仍以文档为断言标准。

1. **发裸 `AT`** → 应返回 `OK`（确认串口通、波特率对）。
2. **发 `ATE0`** → 应返回 `OK`（关闭回显，后续断言才无需处理回显前缀）。
3. **发 `AT+CMEE=1`** → 启用 CME 错误码数字返回（否则部分固件只返通用 ERROR，无法区分错因）。
4. **逐类勘测**：取一条查询指令（如 `AT+CSQ`）、一条设置指令（如 `AT+CMGF=0`）、
   一条测试指令（`AT+CSQ=?`）实测，记录字节级响应（用 `\r\n` 转义可见化）。
5. **记录到本文件第二部分**：新增 `<平台>` 小节，写实测的数据行空格规律、业务码格式、CME 码语义
   （标注「文档未明确，实测所得」，供该平台写用例参考）。
6. **写严格断言时以文档为准**：文档明确的部分据文档写；文档不明的部分参考勘测结果写，
   但断言失败时优先怀疑设备偏差（可能是 bug），而非勘测结果绝对正确。

> 勘测结果应沉淀回本文件，作为该平台的速查。这是 skill「从无到有」覆盖新平台的核心知识资产。
